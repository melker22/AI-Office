# CodeRabbit History Audit

Verification of every CodeRabbit finding recorded in `docs/audit/coderabbit-history.json`
(PRs #1–#10, 114 items: inline, outside-diff, and nitpick comments) against the current
state of the code. Each item was re-read against the file/line it names today and classified:

- **VALID** — the defect still reproduces in the current code.
- **FIXED** — the code was changed and the defect no longer exists; cited with the commit
  (`git log -S` / `git log -L`) or the code that resolves it.
- **N/A** — the code was removed/rewritten so the defect no longer applies in that form, or
  the original finding was itself incorrect.

Resolved-thread status and "Addressed in" labels were **not** treated as evidence — each
verdict below is based on reading the current source.

## Still VALID today (6 of 114)

Grouped by module, most severe first. Everything else in the full table (107 FIXED, 1 N/A) has
been verified fixed in the current code or was never actually a live defect.

### `src/core/Docx.cpp` — DOCX import/export
- **CR-1-009 (Major)** — `loadDocx` still sets `jsonOwnsRevisions` and skips *all* native
  `w:ins`/`w:del`/format-change parsing whenever `word/aioffice.json` has any revision, instead of
  merging native edits with the fallback copy (the matching ODF side was fixed to merge by id).
  **Fix:** when `jsonOwnsRevisions` is true, still parse native marks and dedupe them against the
  JSON revisions by `(blockId, kind, start, end)` — the same merge strategy `Odf.cpp` already uses
  — instead of discarding every native mark outright.

### `.cockpit/fleets/*.yaml` — Fleet orchestration
- **CR-3-032 (Major)** — `task.yaml`'s `adjudicate` node (and the equivalent node in
  `wave16-ctl-cjk.yaml`/`wave17-roundtrip.yaml`/`wave18-fields.yaml`) has no `success_output`, so a
  `verdict:"failed"` does not actually fail the node/loop at runtime, contrary to the inline
  comment's claim — `wave19-pdf.yaml`/`wave20-epub-rtf.yaml` already carry the real fix.
  **Fix:** add a boolean `resolved` field to each node's `output_contract` and set
  `success_output: resolved`, mirroring `wave19-pdf.yaml:211-216`.

### `src/core/Session.cpp` — read-only document guard
- **CR-10-113 (Major)** — `saveDocument` calls `refreshIfFields(doc_, dirty_)` unconditionally,
  so a read-only export (e.g. `.rtf`/`.epub`) can still overwrite cached `stat`/structure-field
  text in the live in-memory document. **Fix:** compute the refreshed fields into the export
  snapshot/copy only, or skip `refreshIfFields` on `doc_` itself when `doc_.readOnly` is true.

### `src/core/FieldExpr.cpp` — field expression refresh
- **CR-10-114 (Minor)** — `refreshIfFields` computes `statPages` before refreshing `if`/`seq`
  structure fields, so a `stat{pages}` field can read a page count taken before a structure-field
  branch change could have altered pagination. **Fix:** run `eachRun(false)` (structure fields)
  before computing `statPages`, or recompute `statPages` after that pass.

### `src/core/Preview.cpp` — text layout performance
- **CR-3-035 (Trivial)** — `blockTextLayout`'s `modelToDisplay` build is still O(M·D) (inner loop
  rescans `displayToModel` from 0 for every model offset), on every paint/caret/hit-test call.
  **Fix:** track one forward pointer across the loop, as `displayToModel` is non-decreasing.

### `qa/wave20-rtf-out.rtf.json` — QA fixture
- **CR-9-096 (Trivial)** — the RTF-escaping check still asserts the substring `"\\u"`, which the
  fixed `\uc1` header always contains, so it can never fail. **Fix:** assert a code-point-specific
  marker from the fixture's Arabic text instead, e.g. `"\\u1605"`.
